# Alchemist's Lattice — dev harnesses

Plain Node scripts, no build step, no test framework. Run from the repo root.

| Command | What it does |
|---|---|
| `node game-027/dev/simtest.mjs` | Headless, in Node. **purity**: `js/sim/`, `js/rng.js` and `js/config.js` never touch the DOM, a renderer, storage, `Math.random` or the clock. **data**: every tile type is connected, at the origin and back after four turns; recipes, foes, potions, enhancements and skills point at real things; every scene's speakers have the portrait it asks for and every branch lands; every painting the game uses is in `art/`. **map**: 200 seeds × 4 chapters: an exploration first, the boss last, a shop, no elite in the first two layers or straight after another, everything reachable and leading on. **levels**: 1,200 generated levels: supplies in whole hands with the small-tile floor, deposits apart, the crucible, foes, a starting board with no full line. **rules**: placing, rows, columns and crosses, scoring, streaks, the deal and its mercy, out of tiles, stuck versus jammed, conceding, deposits peeling and harvesting, refinement (rich lines, the double, the streak, forbidden lines, forgiving, grades), battle (damage, armour, cutting back, attacks, growth, hardening, defeat), every item and skill. **game**: travelling, finishing, rewards, resolve and the redrawn map, the shop, caches, the cauldron, skills, enhancements, scenes, three bosses, the ending and the open road. **determinism**: same seed and commands → same game; saves at three points mid-run play on identically; bad saves are rejected. **bot**: whole campaigns at two skills on `SEEDS` seeds with invariants after every command, and the balance table. `ONLY=purity,data,map,levels,rules,game,determinism,bot`, `SEEDS=n`, `VERBOSE=1`. |
| `node game-027/dev/browsertest.mjs` | Real Chromium + WebGL (SwiftShader), real input. **desktop**: the title, the opening scene clicked through, the map, the brief; a mouse drag, a click-then-click and the keyboard each place a tile; a drag that completes a row clears it; Escape pauses; a real Space on Resume; the Catalyst by key; the bot wins the level; the result; the cauldron, skills and journal by real clicks; Save & Quit → Continue; the shop; the last boss; the ending; the open road; every painting loads. **phones** (touch only, real CDP touches) at 390×844 and 844×390: taps through the title, the scene and the map; a touch drag (the tile floats above the finger) and a tap-tap place tiles; controls ≥ 44 px and on screen; the HUD above the lattice; pause stays open. **nostorage**: plays with `localStorage` throwing. Fails on any console error, page error or failed request. `ONLY=desktop,phones,nostorage`. Screenshots in `dev/shots/`. |
| `node game-027/dev/play.mjs name "js" [waitMs] [w h] [touch]` | Opens the game with `?debug=1`, runs a snippet (`return` prints a value), screenshots to `dev/shots/name.png`. |
| `node game-027/dev/preview.mjs` | Sets up a mid-level moment and writes the 1200×630 launcher picture to `garden/img/games/game-027.jpg`. |
| `node game-027/dev/art/prompts.mjs` | The fal jobs for the paintings, built from the game's data. See [art/README.md](art/README.md). |

The browser scripts need `playwright` (`mkdir -p dev/node_modules && ln -s "$(npm root -g)/playwright" dev/node_modules/playwright` at the repo root, then `ln -s ../../dev/node_modules game-027/dev/node_modules`). No web server is needed: [serve.mjs](serve.mjs) serves the repo from disk through Playwright's request routing as `http://game.local/`, stubs Google Fonts and fetches three.js from unpkg.com, or from a local copy in `dev/package` (`npm pack three@0.165.0`) or `THREE_PKG`. Set `BASE=http://127.0.0.1:8111` to use a real server instead; `PW_CHROMIUM_PATH` for an unusual Chromium.

SwiftShader draws a few frames a second and the loop caps a frame at 0.05 s, so the tests wait on state, never on the clock, and `ready()` waits for the level to take input (no screen, no dialog, no queued events) and two more frames. Passing tests don't mean the screen shows anything: look at the screenshots.

## Debug hooks (`?debug=1`)

`window.__al`: `G` (the game), `mode` (title, map, level, shop, ending), `frames`, `dlg` (the scene playing), `seen` (a count of every sim event drained), `view`, `ui`, `audio`, `input`, `ctl` (the play controller), `art`; `start(seed)` (a new apprenticeship, on the map), `skipScenes()`, `go(nodeId, enh)`, `act(cmd)`, `autoplay(on, skill)` (the bot plays the level), `autorun(on, skill)` (the bot plays the campaign through the screens), `ff(n, skill)` (n bot moves at once), `toMap()`, `save()`, `setG(g)`. `view.toScreen(fx, fy)` maps cell coordinates to client px, `view.slots` are the hand slots in cell coordinates, `view.cellPx()` is a cell's size on screen. `&fast=N` speeds the bots; `&art=0` loads no paintings (the code-drawn stand-ins show).
